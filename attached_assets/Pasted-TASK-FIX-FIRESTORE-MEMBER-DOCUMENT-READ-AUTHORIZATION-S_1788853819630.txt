TASK: FIX FIRESTORE MEMBER-DOCUMENT READ AUTHORIZATION

SCOPE: ONE SECURITY FIX ONLY
READ/WRITE SCOPE MUST BE STRICTLY LIMITED

We confirmed a real authorization bug in:

firestore.rules

Current rule:

match /spaces/{spaceId}/members/{uid} {
  allow read: if isActiveMember(spaceId);
  allow create, update, delete: if false;
}

PROBLEM:

The read rule checks only whether the requesting user is an active member
of the Space.

It does NOT verify that the requested {uid} equals request.auth.uid.

Therefore, an active member could read another member's document inside
the same Space.

==================================================
REQUIRED FIX
==================================================

Change ONLY the member-document read condition so that a user can read
the member document only when:

1. the user is authenticated
2. the user is an active member of the Space
3. the requested member document UID equals request.auth.uid

The resulting condition must enforce:

isActiveMember(spaceId) && uid == request.auth.uid

Keep create/update/delete denied.
