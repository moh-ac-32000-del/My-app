# Stable Baseline — Checkpoint & Full Project Archive

أريد الآن حفظ الحالة الحالية للمشروع كنقطة مستقرة فقط.

هذه المهمة للحفظ والتوثيق والنسخ الأرشيفية فقط.

## ممنوع منعًا باتًا

- تعديل أي كود.
- إصلاح أي شيء.
- إعادة تنسيق الملفات.
- تثبيت أي حزمة.
- تحديث أي dependency.
- تشغيل npm/pnpm install.
- تعديل package.json.
- تعديل pnpm-lock.yaml.
- تعديل .replit.
- تعديل Workflow.
- تشغيل Expo أو Metro.
- تشغيل Browser.
- تشغيل Playwright.
- تشغيل E2E.
- تشغيل Screenshots.
- تعديل بيانات AsyncStorage.
- حذف أي بيانات.
- تنفيذ Migration.
- تنفيذ Firestore.
- تنفيذ Cloud Sync.

## أولًا: Git Checkpoint

تحقق من حالة Git الحالية.

أريد حفظ الحالة الحالية كنقطة مرجعية واضحة.

إذا كان إنشاء Commit آمنًا ومسموحًا به، أنشئ Commit واحد فقط بعنوان واضح مثل:

Stable baseline: Firebase Auth + Local Space Isolation

لا تنشئ أي Commit آخر.

إذا كان إنشاء Commit غير ضروري أو غير ممكن، لا تحاول الالتفاف على ذلك، واكتفِ بتوثيق commit الحالي.

## ثانيًا: فحص الحالة

سجّل:

- branch الحالي.
- commit الحالي قبل الحفظ.
- commit النهائي بعد الحفظ إن تم إنشاء Commit.
- git status.
- git diff.

يجب التأكد من عدم وجود تغييرات غير مقصودة.

## ثالثًا: إنشاء نسخة أرشيفية كاملة

أنشئ نسخة كاملة من المشروع خارج شجرة المشروع حتى لا تدخل النسخة داخل نفسها.

يجب أن تتضمن النسخة:

- Source Code
- Assets
- Tests
- package.json
- pnpm-lock.yaml
- إعدادات المشروع
- ملفات التعليمات
- .agents
- Git metadata إذا كان ذلك ممكنًا
- جميع الملفات المصدرية المطلوبة لإعادة بناء المشروع

لا تضمن:

- node_modules
- cache
- Expo generated files
- dist
- build outputs
- TypeScript build info
- أي ملفات مؤقتة أو generated يمكن إعادة إنشائها من lockfiles

لا تحذف هذه الملفات من المشروع نفسه؛ فقط لا تضعها في الأرشيف.

## رابعًا: لا تنشئ الأرشيف داخل نفسه

المسار يجب أن يكون خارج مجلد المشروع.

مثلًا:

/home/runner/project-backups/

ولا تضع archive داخل:

/home/runner/workspace/

إذا كان ذلك سيؤدي إلى تضمينه في نفسه.

## خامسًا: الملفات التوثيقية

إذا كانت ملفات التوثيق الحالية موجودة بالفعل، احتفظ بها كما هي.

لا تنشئ توثيقًا جديدًا إلا إذا كان ضروريًا جدًا.

لا تغيّر محتوى التطبيق من أجل التوثيق.

## سادسًا: معلومات الحالة التي يجب توثيقها

وثّق في التقرير:

### الميزات المكتملة حاليًا

- Firebase Authentication
- Email/Password
- Firebase session persistence
- Space Identity
- Local Space Isolation
- Backup/Restore المحلي
- WhatsApp Archive Sharing

### الميزات غير المنفذة

- Firestore
- Cloud Sync
- Cloud Backup
- Spaces UI المتقدمة
- Multiple cloud users/roles
- Cloud migration
- Multi-device synchronization

### البيانات

أكد أن:

- StoreProfile.id لم يتغير.
- storeId لم يتغير.
- local-store لم تُحذف.
- local-store لم تُنقل.
- Backup formatVersion ما زال 1.
- Backup/Restore يعمل.
- بيانات Spaces معزولة محليًا.

## سابعًا: معلومات النسخة

بعد إنشاء archive:

أعطني:

- المسار الكامل للنسخة المستخرجة.
- المسار الكامل للملف المضغوط.
- حجم الملف المضغوط بالبايت وMB.
- عدد الملفات داخل النسخة.
- SHA-256 للملف المضغوط.
- تأكيد أن archive قابل للقراءة.
- تأكيد أن فهرس archive سليم.

## ثامنًا: سلامة النسخة

تحقق فقط من أن:

- archive موجود.
- archive قابل للفتح/قراءة الفهرس.
- الملفات الأساسية موجودة.
- SHA-256 تم حسابه.
- النسخة لا تحتوي نفسها بشكل متكرر.

لا تشغّل التطبيق.

## تاسعًا: البيانات الموجودة على الهاتف

لا تحاول نسخ AsyncStorage إلى الأرشيف.

لا تعدّل AsyncStorage.

اذكر بوضوح في التقرير أن بيانات التطبيق المحلية ليست جزءًا من Source Archive، وأن Backup JSON هو وسيلة حفظ بيانات المستخدم الحالية.

## عاشرًا: الرصيد

لا تنفذ أي مهمة تطويرية أخرى.

لا تستخدم الرصيد في إصلاحات أو تحسينات.

بعد إنشاء النسخة والتقرير توقف تمامًا.

## التقرير النهائي

أرسل تقريرًا واضحًا يحتوي:

1. Git branch.
2. Git commit.
3. Git status.
4. هل تم إنشاء Commit جديد؟
5. مسار النسخة المستخرجة.
6. مسار archive المضغوط.
7. حجم archive.
8. عدد الملفات.
9. SHA-256.
10. تأكيد سلامة archive.
11. الميزات المكتملة.
12. الميزات المؤجلة.
13. تأكيد عدم تعديل الكود أو البيانات.
14. أي مشكلة أو ملاحظة.

ثم توقف تمامًا.

لا تبدأ أي Task جديدة.
