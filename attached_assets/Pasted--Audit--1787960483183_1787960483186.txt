مهم جدًا جدًا:

هذه المهمة للفحص والتحليل فقط.

لا تعدّل أي ملف.

لا تنشئ ملفات جديدة.

لا تحذف أي ملف.

لا تعيد هيكلة الكود.

لا تصلح أي مشكلة.

لا تضف أي ميزة.

لا تشغّل Agent لتنفيذ إصلاحات تلقائية.

لا تبدأ الدفعة الثانية.

لا تضف Firebase.

لا تضف Authentication.

لا تضف العملاء أو الديون أو السداد.

لا تضف المخزون.

لا تضف سعر الصرف.

الهدف الوحيد هو معرفة مدى جودة البنية الحالية وقابليتها للتطوير لاحقًا.

1. افحص Architecture

راجع بنية المشروع الحالية بالكامل، وخصوصًا:

- app/
- components/
- context/
- hooks/
- constants/
- services/
- types/
- data/
- assets/

حدد هل تقسيم المسؤوليات مناسب أم توجد ملفات تتحمل مسؤوليات كثيرة.

2. قابلية التعديل مستقبلًا

قيّم هل يمكن إضافة الميزات القادمة بدون التسبب في مشاكل في الميزات الموجودة.

خصوصًا:

- العملاء.
- الآجل.
- السداد.
- اليومية.
- الصندوق.
- التذكيرات.
- المساحات المشتركة.
- المستخدمون والصلاحيات.
- Firebase.

أريد معرفة الأماكن التي قد تسبب مشاكل عند إضافة هذه الميزات.

3. State Management

راجع:

- StoreContext.
- أي Context آخر.
- useState.
- useEffect.
- AsyncStorage.

تحقق من:

- وجود أكثر من مصدر للحالة نفسها.
- احتمالية stale state.
- Race conditions.
- تحديثات متزامنة قد تستبدل بيانات أحدث.
- مشاكل عند إعادة تشغيل التطبيق.
- مشاكل عند تحميل البيانات بشكل غير متزامن.

4. AsyncStorage

افحص طريقة التخزين الحالية.

حدد:

- ما الذي يتم تخزينه؟
- أين يتم تخزينه؟
- من المسؤول عن الكتابة؟
- من المسؤول عن القراءة؟
- هل توجد أكثر من جهة تعدل البيانات نفسها؟
- هل توجد احتمالية فقدان بيانات؟
- هل توجد migrations؟
- هل أسماء المفاتيح منظمة؟
- هل يمكن نقل البيانات لاحقًا إلى Firebase بسهولة؟

لا تغير أي شيء.

5. Theme والألوان

راجع:

- constants/colors.ts
- useColors
- أي مكونات تستخدم الألوان مباشرة.

تحقق من عدم وجود:

- ألوان Accent ثابتة داخل الصفحات.
- Hex colors موزعة عشوائيًا.
- مصادر متعددة للـTheme.
- مكونات تتجاهل Theme المركزي.

حدد أي مشكلة فقط.

6. i18n

راجع:

- constants/i18n.ts
- useI18n
- StoreContext
- جميع الصفحات والمكونات.

تحقق من:

- النصوص الثابتة.
- مفاتيح ترجمة ناقصة.
- مصادر متعددة للغة.
- مشاكل RTL/LTR.
- أي استخدام مباشر للغة بدل النظام المركزي.

لا تعدل شيئًا.

7. Currency System

راجع نظام العملات الحالي فقط.

تحقق من:

- currencies.ts
- formatMoney()
- StoreContext
- Settings
- Dashboard
- أي مكان يعرض الأموال.

تأكد من عدم وجود:

- عملة محفوظة كنص حر.
- رموز عملات مكتوبة مباشرة داخل الصفحات.
- تنسيق مالي مكرر.
- Currency Conversion.
- Exchange Rate.

لا تضف أي نظام جديد.

8. Navigation

راجع:

- _layout
- AppShell
- جميع مسارات app.

تحقق من:

- Stack.
- navigation.
- replace.
- الروابط.
- الصفحات المكررة.
- احتمال تراكم الصفحات.
- Back behavior.
- RTL/LTR navigation.

9. Floating Action Button

راجع التنفيذ الحالي للـFloating Action Button الذي تم إنشاؤه في Task #1.

تحقق من:

- هل يوجد instance واحد أم عدة instances؟
- هل مكانه مركزي؟
- هل يمكن تطويره لاحقًا؟
- هل يعتمد على الصفحة الحالية بشكل زائد؟
- هل يمكن إضافة إجراءات جديدة بسهولة؟
- هل يمكن ربطه لاحقًا بالعمليات الحقيقية بدون إعادة بنائه؟

10. Reusability

حدد المكونات التي يمكن إعادة استخدامها.

خصوصًا:

- Glass cards.
- Buttons.
- Dialogs.
- Headers.
- Lists.
- Input fields.
- Customer selector مستقبلًا.
- Money input مستقبلًا.
- Quick actions.

أريد معرفة هل سنضطر إلى نسخ نفس الكود عند بناء صفحات العملاء والآجل والسداد.

11. Data Models

راجع:

"types/"

وحدد هل النماذج الحالية مناسبة للتوسع.

خصوصًا إمكانية إضافة مستقبلًا:

User
Workspace
WorkspaceMember
Customer
Transaction
Payment
Debt
Reminder

لا تنشئ هذه النماذج الآن.

فقط قيّم هل البنية الحالية تسمح بإضافتها بطريقة منظمة.

12. Firebase readiness

لا تقم بتوصيل Firebase.

فقط افحص هل فصل الخدمات الحالي يسمح مستقبلًا باستبدال التخزين المحلي بمصدر بيانات حقيقي.

أريد معرفة هل الواجهة مرتبطة مباشرة بـAsyncStorage في أماكن كثيرة، أم أن هناك طبقة يمكن استبدالها لاحقًا.

13. Android / iOS

راجع المشروع من ناحية Expo / React Native.

حدد أي كود قد يكون:

- Web-only.
- Android-only.
- iOS-only.

خصوصًا بعد مشاكل Expo Web التي ظهرت أثناء اختبار Task #1.

لا تصلحها.

فقط حددها.

14. Performance

ابحث عن المشاكل المحتملة:

- re-renders غير ضرورية.
- Context واسع جدًا.
- useEffect غير ضروري.
- عمليات AsyncStorage متكررة.
- قوائم غير محسنة.
- Components تعاد بدون حاجة.

لا تقم بأي تحسين.

15. Security

راجع الوضع الحالي فقط.

خصوصًا:

- AsyncStorage.
- بيانات المستخدم.
- بيانات المتجر.
- أي بيانات حساسة.

لا تضف Authentication أو Firebase.

أريد فقط معرفة المخاطر الحالية التي يجب أن نعالجها قبل إطلاق النسخة الحقيقية.

16. Code Quality

افحص:

- TypeScript.
- any.
- duplicate code.
- dead code.
- unused imports.
- naming.
- circular dependencies.
- coupling بين الملفات.

إذا وجدت مشكلة، سجلها فقط.

17. اختبارات موجودة

راجع الاختبارات الحالية إن وجدت.

حدد:

- ما الذي يتم اختباره؟
- ما الذي لا يتم اختباره؟
- أهم الاختبارات التي سنحتاجها لاحقًا.

لا تنشئ اختبارات جديدة في هذه المهمة.

18. التصنيف

صنف كل ملاحظة إلى:

🔴 Critical
قد تسبب فقدان بيانات أو تمنع تطوير المشروع.

🟠 Important
قد تسبب مشاكل لاحقًا ويُفضل إصلاحها قبل التوسع.

🟡 Minor
مشكلة صغيرة يمكن تأجيلها.

🟢 Good
جزء جيد ولا يحتاج إلى تعديل.
